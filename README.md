# music

**Личный Telegram-медиабот с родным плеером Telegram**, не связанный с VOID/Soodoo VPN. Старый VPN-код удалён из текущего дерева `main`, но доступен в истории Git.

## Реализовано

- Только приватный чат владельца (точный Telegram ID в настройках).
- Приём реального аудио из Telegram, хранение `file_id` и метаданных в SQLite.
- ❤️ «Мне нравится», собственные плейлисты, добавление, удаление, переименование, перестановка.
- 🌊 Локальная «Волна» и «Открытия» на основе сохранённых треков и явных оценок.
- Устойчивые очереди: выдача по 10 треков, кнопка «Ещё 10» и история **отправленных** песен.
- Инлайн-кнопки под треками, меню библиотеки и плейлистов; поиск в своей медиатеке.
- Docker Compose без портов наружу, SQLite, тесты в GitHub Actions.

Автоматической загрузки из YouTube, фильмов и аниме, Mini App или внешних рекомендательных сервисов **пока нет**. Для этого нужны отдельные адаптеры, проверка разрешённого доступа, технических лимитов и контента. Ссылка сама по себе не превращается в нативное аудио Telegram.

## Запуск

Python 3.12+.

1. `python -m pip install -e ".[dev]"`
2. `cp .env.example .env` и заполнить `BOT_TOKEN`, `OWNER_TELEGRAM_ID`.
3. `python -m music_bot.main` (long polling).

Альтернатива: `docker compose up -d --build`. База в Docker — в именованном томе `music_data`; не удаляй том при обновлении.

## Развёртывание и безопасность

Сервер Soodoo не меняли; на освобождённом старом сервере разворачивать только после завершения VPN-миграции и периода отката. Не выкладывать токены/базу/медиа в Git. Отдельный токен и owner ID обязательны. SQLite с плейлистами необходимо регулярно бэкапить. Нативный Telegram-плеер не сообщает боту о реальных пропусках и количестве прослушиваний.
