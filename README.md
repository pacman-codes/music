# music

Личный Telegram-медиабот с нативным Telegram-плеером. Это новая кодовая база вместо VOID. В актуальной ветке main нет старых VPN/подписочных/платёжных файлов.

## Уже в каркасе
- Только владелец по OWNER_TELEGRAM_ID в приватном чате.
- Приём Telegram-аудио и хранение file_id в SQLite (без копирования медиа на VPS).
- Главный плейлист «Мне нравится», свои плейлисты, добавление треков.
- Локальная «Волна» с учётом лайков, дизлайков и разнообразия исполнителей.
- Отправка подборки аудиосообщениями с родным плеером Telegram.
- Docker Compose без внешних портов, тесты и GitHub CI.

## Запуск
Python 3.12+.

1. Установить зависимости: python -m pip install -e ".[dev]"
2. Скопировать .env.example в .env; задать BOT_TOKEN и OWNER_TELEGRAM_ID.
3. Запустить: python -m music_bot.main
4. Или: docker compose up -d --build

## Команды
/start — справка
/library — библиотека с ID треков
/liked — понравившиеся
/like ID — лайк
/dislike ID — скрыть из Волны
/playliked — отправить понравившиеся
/newplaylist Название — создать плейлист
/playlists — показать плейлисты
/addto ПЛЕЙЛИСТ_ID ТРЕК_ID — добавить песню
/playplaylist ID — отправить плейлист
/wave — волна из сохранённых треков

Пришли боту аудиофайл, чтобы добавить его в библиотеку.

## Ограничения
Нативный Telegram-плеер не сообщает боту об автоматическом пропуске или дослушивании. Внешнюю ссылку нельзя просто обернуть в нативный плеер: нужен загруженный Telegram audio/video файл. Отправка группы аудио не является гарантированной бесконечной очередью.

Это отдельный проект: старый production Soodoo не трогаем. Развёртывать на освобождённом старом сервере только после миграции VPN и проверки возможности отката. Git-история старого кода остаётся в предыдущих коммитах.
