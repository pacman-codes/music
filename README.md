# music

Личный музыкальный Telegram-бот с собственными плейлистами, «Волной» и первой версией Mini App. **Главный плеер — нативный Telegram.** Репозиторий полностью заменил старое дерево VOID в ветке main; история прежних коммитов осталась.

## Реализовано в GitHub

- Владелец-only Telegram-бот (aiogram), библиотека на SQLite.
- Приём аудиофайлов, Telegram file_id, «Мне нравится», собственные плейлисты и поиск.
- Сохранённую песню можно мгновенно отправить в родной плеер через `/play ID`, кнопку «▶ Слушать» под песней и списком результатов поиска или через Mini App. Повторного скачивания нет.
- Переименование, удаление, добавление и изменение порядка песен в плейлисте.
- Локальная «Волна»: независимые оценки 1–10, любимые песни, учёт вручную отмеченных скипов/дослушиваний, штраф за повторы.
- **Пассивное улучшение рекомендаций:** без новых опросов/кнопок — история доставленных песен с затухающим штрафом за повтор (не считается прослушиванием), слабые связи между песнями пользовательских плейлистов, снижение повторов исполнителя подряд и чередование категорий. Существующие лайки, оценки и исключения важнее этих сигналов.
- **Волна 2.0:** воспроизводимые треки из трёх категорий — знакомые, похожие по любимым исполнителям и остальные новые для предпочтений песни. Соотношения 60/25/15, 80/15/5, 35/30/35; настроить через `/mix` или Mini App. Каждая следующая порция пересчитывается по актуальным оценкам. Результаты внешнего каталога без аудиофайла не выдаются за воспроизводимые.
- Одна панель оценок каждого трека порции, история отправленных треков. Обычные плейлисты сохраняют свой фиксированный порядок.
- Защита от двойных нажатий «Ещё 10»: кнопка привязана к позиции очереди, старые карточки не перескакивают через треки.
- `/continue` и кнопка «▶ Продолжить» восстанавливают последнюю сохранённую очередь после ошибки отправки карточки управления, без повторной отправки уже принятых Telegram треков. Отправки одной очереди из bot и web сериализуются общей SQLite-блокировкой.
- Mini App: библиотека, поиск, оценка 1–10, ручные кнопки «Пропустил»/«Дослушал», плейлисты и отправка музыки в чат.
- **Управляемая очередь:** /queue, /next, /append, /qmove, /qremove, /qfilter и кнопки в Mini App; редактирование только будущих аудио, фильтры по оценке, избранному и отправкам за день для радио. Блокировки исключают редактирование прямо во время отправки.
- **Новая музыка:** поиск записей MusicBrainz, радио похожих исполнителей ListenBrainz и отдельный список «📌 Отложено». Внешние результаты — метаданные, не аудиофайлы.
- Доступ к музыкальному каталогу **без Mini App**: команды `/find`, `/radio`, `/saved` и обычные кнопки Telegram для добавления находок в отложенное.
- **Совпадения MusicBrainz:** ручное подтверждение MBID для уже загруженной песни, раздельные статусы «возможно совпадает» и «подтверждено»; радио по отдельному треку с точным Artist MBID при наличии. Уже загруженные записи можно запускать прямо из MusicBrainz-поиска, а повторный импорт не перезапишет идентичность другого файла.
- **✨ Для меня:** подборка ListenBrainz на основе до трёх любимых/высоко оценённых артистов: rank fusion поднимает кандидатов, рекомендованных несколькими любимыми артистами, с мягким разнообразием исполнителей и консервативным исключением явно отвергаемых артистов. При отсутствии лайков и оценок подборка сама стартует от исполнителей уже сохранённой музыки (слабый сигнал, не факт прослушивания). Результаты остаются метаданными, пока аудио не загружено в Telegram.
- **Опциональный импорт:** прямой MP3/M4A с заранее разрешённого HTTPS-хоста, временное хранение до 45 МБ, отправка `sendAudio`, привязка настоящего Telegram `file_id` к MusicBrainz MBID. По умолчанию выключен.
- Защита от одновременного импорта того же файла в двух процессах через общие SQLite leases; ошибка Telegram не создаёт фиктивного трека. Глобальная блокировка допускает только одну активную загрузку на весь bot+web, чтобы не перегрузить небольшой VPS.
- **YouTube (opt-in):** поиск без ключа API через `yt-dlp`, импорт аудио по найденному VIDEO_ID с конвертацией FFmpeg в MP3 и отправкой в нативный Telegram-плеер. Ограничения: видео до 20 минут, временный диск до 80 МБ, итоговый файл до 45 МБ и таймаут 120 секунд. Два независимых выключателя для поиска и скачивания, оба по умолчанию выключены.
- **Переход из MusicBrainz в YouTube:** вероятные совпадения по названию, исполнителю и длительности с предупреждением о live/remix и ручным выбором. Никакого автоматического скачивания по похожести названия. **После подтверждения выбранного варианта** YouTube-аудио получает точные заголовок и артиста из MusicBrainz и связь MBID→Telegram file_id. При конфликте существующей идентичности привязка запрещена.
- **🧬 AcoustID (opt-in):** `/fingerprint ID` или кнопка Mini App снимает Chromaprint-отпечаток с существующего Telegram-файла, ищет MusicBrainz-кандидатов и показывает возможные дубли. После **ручного подтверждения** команды `/tag ID` и кнопка Mini App применяют название/исполнителя к SQLite-библиотеке, не изменяя бинарный файл или ID3 в Telegram. Нужны `ACOUSTID_CLIENT_KEY` и `fpcalc`.
- **📅 Находки недели:** новые релизы ListenBrainz и персональные рекомендации по любимым артистам, `/weekly` и Mini App. Опциональный запуск однократной еженедельной отправки через `python -m music_bot.weekly_notify --send`; расписание на сервере настраивается отдельно, сейчас не включено.
- **🔒 Профиль для пересмотра рекомендаций:** команда `/tasteexport` отправляет полный JSON библиотеки только владельцу — треки, даты новых добавлений (после обновления базы), оценки, избранное, плейлисты и факты отправки без Telegram file_id и секретов. Опциональная `/tastesync` загружает такой профиль в **отдельный проверенный приватный GitHub-репозиторий**, только если он настроен; для периодического анализа и доработки рекомендаций по запросу. Публичный `music` репозиторий не используется.
- **📊 Music Wrapped:** `/wrapped 30d` и карточки Mini App — лидеры по отправкам, избранное, оценки, вручную отмеченные события, недельный график. Не выдаёт отправку за реальное прослушивание.
- **🎞 Аниме:** поиск по AniList, частный список «в планах/смотрю/просмотрено/на паузе/брошено», прогресс по сериям и оценка 1–10 в чате и Mini App. Это метаданные, а не автоматический видеоплеер.
- **🎬 Фильмы и сериалы:** отключаемый TMDB-поиск, статусы, собственные оценки и прогресс по сезонам/сериям. TMDB требует отдельного приватного `TMDB_READ_TOKEN`; без него раздел не появляется. Пока без потокового воспроизведения.
- Ограничение запросов MusicBrainz (не чаще одного обращения за 1,1 секунды **на общую SQLite-базу bot + web**), кеш SQLite, запрет произвольных URL/редиректов и лимиты размера ответа.
- Backend проверяет подпись Telegram initData, временную метку и ID владельца.
- Контейнеры bot и web, GitHub CI, автоматические тесты. В CI проверяются сборка обычного Docker-образа и запуск диагностического CLI внутри контейнера. `.dockerignore` исключает секреты, SQLite и медиа из контекста сборки.
- Сквозной **офлайн** интеграционный тест: YouTube-поиск → импорт MP3 → ответ Bot API → Telegram `file_id` → повторное использование → выбор песни для «Волны».

**Ещё нет:** автоматического нахождения доступного аудиофайла по записи MusicBrainz, точного автоматического сопоставления YouTube с MusicBrainz, полноценного смешивания новых файлов в «Волну», **воспроизведения фильмов/аниме**, полноценного каталога фильмов и готового публичного HTTPS. **YouTube-импорт написан, но не проверен на реальном YouTube или телефоне**, а сам сервис может ограничивать извлечение аудио. Прямая загрузка разрешённых MP3/M4A по ссылке — отдельная, отключённая по умолчанию функция. Mini App/плеер пока не проверяли с настоящего телефона.

## Быстрый запуск локально

Python 3.12+; запускать только с собственным токеном от BotFather.

1. `python -m pip install -e ".[dev]"`
2. `cp .env.example .env` — задать BOT_TOKEN и OWNER_TELEGRAM_ID.
3. `python -m music_bot.main` — бот (long polling).
4. `uvicorn music_bot.api:create_app --factory --host 127.0.0.1 --port 8085` — локальный backend Mini App.

Или `docker compose up -d --build`. Для YouTube-пакета (yt-dlp + FFmpeg) в локальном `.env` поставить `MUSIC_WITH_YOUTUBE=true` и нужные `MUSIC_ENABLE_YOUTUBE_SEARCH`, `MUSIC_ENABLE_YOUTUBE_DOWNLOAD`, затем пересобрать. По умолчанию образ остаётся лёгким, а поиск и скачивание отключены. В Compose web доступен только на 127.0.0.1:8085. Для Telegram Mini App **обязателен реальный HTTPS адрес** и WEBAPP_URL в .env; прямой HTTP localhost на телефоне не подходит. До настройки адреса бот работает без веб-кнопки, через обычные команды.

Локальные данные SQLite: путь MUSIC_DB_PATH (по умолчанию data/music.db); в Docker — volume music_data. Не удаляй volume при обновлении.

Ручной согласованный backup: `python -m music_bot.backup --database data/music.db --output backups`. Скопируй созданный sqlite3-файл **за пределы сервера**, иначе при его потере бэкап тоже пропадёт. Для контейнеров путь базы — /app/data/music.db.

Обслуживание базы без удаления медиатеки: `python -m music_bot.maintenance --database data/music.db` (только отчёт), затем при необходимости и **после бэкапа** добавь `--apply`. Удаляются исключительно устаревшие кеши, старые очереди и технические события; лайки, оценки, библиотеки, списки фильмов и аниме сохраняются.

**Диагностика перед первым запуском:** `python -m music_bot.doctor` (локальная проверка настроек, свободного места, SQLite и yt-dlp/FFmpeg, без скачивания медиа и изменения базы). `python -m music_bot.doctor --online` дополнительно только читает Bot API (`getMe` и доступность чата владельца); не отправляет сообщений и не показывает токен. Команда работает и внутри Docker: `docker compose run --rm music python -m music_bot.doctor`.

**Подготовка реального запуска:** добавить BotFather-токен и Telegram ID владельца только в приватный `.env`, сделать `/start` своему боту, выполнить doctor, после подготовки отдельного сервера запустить bot и затем проверить один разрешённый MP3 через Telegram. Не переносить приложение на Soodoo production до завершения его миграции.

/rate ТРЕК_ID 1-10, /skip ТРЕК_ID, /finished ТРЕК_ID,
/find Песня /radio Исполнитель /radiotrack ТРЕК_ID /recommend /saved,
/identify ТРЕК_ID /unmatch ТРЕК_ID,
/import MBID https://разрешённый-хост/track.mp3,
/yt Название /ytget VIDEO_ID /ytfor MBID (по умолчанию выключены),
/anime Название /animelist /animestatus ID plan|watch|done|hold|drop,
/animeprogress ID Количество /animerate ID 1-10,
/film Название /films /filmstatus movie|tv ID plan|watch|done|hold|drop,
/filmprogress TV_ID Сезон Серия /filmrate movie|tv ID 1-10,
/playliked, /newplaylist Название, /playlists, /playlist ID,
/renameplaylist ID Название, /deleteplaylist ID,
/addto ПЛ_ID ТРЕК_ID, /removefrom ПЛ_ID ТРЕК_ID, /move ПЛ_ID ТРЕК_ID ПОЗИЦИЯ,
/playplaylist ID, /wave, /mix explore, /queue, /next ID, /append ID,
/qmove ОТ КУДА, /qremove ПОЗИЦИЯ, /qfilter rating 7,
/fingerprint ID, /tag ID, /weekly, /wrapped 30d, /tasteexport, /tastesync, /continue, /discover.

HTML-виджет с оценкой 1–10 создан **только как прототип** и не отправляется ботом: Telegram временно блокирует отправку виджетов обычными production-ботами (issue tdlib/telegram-bot-api#947), а aiogram ещё не поддерживает 10.4. Рабочий интерфейс оценок — стандартные Telegram inline-кнопки и Mini App. Внешний URL не становится нативным аудио без реальной загрузки в Telegram.

**Soodoo production не изменён.** Развёртывание на старом сервере — только после завершения переноса VPN и периода отката. Никакие токены или базы Soodoo не использовать.
