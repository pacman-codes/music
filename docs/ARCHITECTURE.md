# Архитектура

Основная цель: искать музыку, фильмы и аниме, но воспроизводить присланные медиа родным Telegram-плеером.

Сейчас: пользователь -> aiogram polling bot -> SQLite (tracks, playlists, likes, dislikes). Храним file_id Telegram, а не медиа на VPS. Команда /wave подбирает из локальной библиотеки и отправляет порцию максимум 10 файлов.

Будущая схема:
- Telegram Mini App: поисковый UX, плейлисты, настроение, переключатель знакомое/новое. Не отвечает за фоновое аудио.
- API FastAPI: проверка подписанного initData и OWNER_TELEGRAM_ID, хранилище/очереди.
- CatalogAdapter: поиск MusicBrainz, Last.fm, ListenBrainz, TMDB и AniList; результаты — метаданные, не воспроизводимые файлы.
- RecommendationEngine: кандидаты из ListenBrainz/Last.fm + свои лайки, фильтрация ремиксов/live, жанры, diversity, буфер незнакомой музыки.
- SourceResolver: подключаемые правомерные источники HTTP/файлов/облаков; проверки SSL, редиректов, SSRF, размера, контентного типа и ограничений провайдера.
- TelegramArchive: upload/copy в приватный канал и привязка file_id к записи в базе.
- Optional worker: квотируемые загрузки, конвертация без бесконтрольного расхода памяти и диска.

Нельзя просто превратить внешнюю HTTP/HLS/torrent ссылку в нативный Telegram аудио/видеоплеер; Telegram должен получить реальный файл. Для видео больше лимита Bot API нужны отдельно проверенные пути загрузки и ограничения.

Не смешивать проект с Soodoo. Никакие текущие секреты, DNS, VPN-ноды или данные пользователей Soodoo не должны попадать в music.
