# YouTube для личного music-бота (опционально)

Статус на 14 ноября 2026 года: исходники реализованы и покрываются офлайн-тестами; **на реальном YouTube, телефоне и сервере не проверялось**. Не считать это гарантией успешного скачивания любого ролика.

## Возможности

- `/yt название`: поиск до 6 видеозаписей через `yt-dlp ytsearch` без ключа YouTube Data API.
- `/ytfor MBID`: варианты для найденной MusicBrainz-записи; сравнение названия, имени исполнителя и длительности, предупреждение об отличающихся live/remix-версиях. В Mini App доступна кнопка «▶ Найти на YouTube» в карточке каталога.
- В Mini App: отдельная поисковая секция, которая появляется только при включении `MUSIC_ENABLE_YOUTUBE_SEARCH`.
- В найденных результатах — title, channel, duration и строгий video_id длиной 11 символов, а не произвольный URL. Пока файла нет, результат не считается playable.
- `/ytget VIDEO_ID` или кнопка «🎧 В Telegram»: при включённой загрузке бот пытается получить аудио, FFmpeg конвертирует в MP3, бот отправляет его через `sendAudio`, запоминает `file_id` и `file_unique_id`.
- Повторное обращение к уже загруженному VIDEO_ID повторно использует Telegram file_id. Временные файлы удаляются.

## Отдельная сборка в Docker

Настрой в приватном `.env` (НЕ выкладывай токен в GitHub):

```env
MUSIC_WITH_YOUTUBE=true
MUSIC_ENABLE_YOUTUBE_SEARCH=true
MUSIC_ENABLE_YOUTUBE_DOWNLOAD=false
```

`MUSIC_WITH_YOUTUBE=true` добавляет в Docker-сборку `yt-dlp` и FFmpeg (более тяжёлый образ). Для загрузки потребуется вручную изменить последний флаг на true после проверки прав на используемый контент. Для поиска можно оставить `MUSIC_ENABLE_YOUTUBE_DOWNLOAD=false`.

`docker compose up -d --build` — только на отдельном подготовленном сервере music. Никакие контейнеры, домены, базы и ресурсы Soodoo не затрагивать до завершения миграции VPN.

В локальном Python-окружении: `python -m pip install -e ".[youtube,dev]"`, также должен быть установлен FFmpeg с ffprobe в PATH.

## Ограничители и безопасность

- Только YouTube VIDEO_ID из предыдущего поиска; произвольный URL или имя файла не передаётся subprocess.
- Системная команда выполняется как отдельный процесс `python -m yt_dlp`, **без shell=True**, без чтения конфигов yt-dlp и без передачи BotFather-токена.
- Поиск ограничен 90 символами, 8 результатами и 25 секундами; скачивание только одного найденного видео.
- Видеоролики длиннее 20 минут исключаются; прямой HTTP response может не содержать duration, поэтому при загрузке есть отдельный фильтр длительности.
- Max input filesize 40 МБ (best-effort флаг yt-dlp), временная папка максимум 80 МБ, готовый MP3 максимум 45 МБ, subprocess не дольше 120 сек. Это не замена ОС-квотам по CPU/RAM; на старом VPS нужен внешний мониторинг.
- Для одного и того же видео работает общая SQLite lease-блокировка между Telegram-ботом и веб-процессом. Другая попытка получает «уже загружается»; после ошибки блокировка освобождается, а после аварии сама истекает (15 минут). Для ограничения CPU и временного диска дополнительно действует **одна общая capacity lease на всю загрузку**: второй импорт другого файла вернёт «сервер сейчас загружает другой файл». У очереди на ожидание пока нет фонового воркера; запрос нужно повторить.
- В Docker контейнеры получают /tmp на tmpfs с квотой 128 MiB, чтобы даже некорректное скачивание не забило диск хоста. Это память, которая потребляется по мере заполнения tmpfs; на VPS с очень маленькой RAM проверить лимиты перед включением.
- Если YouTube-кандидат найден из MusicBrainz через /ytfor или кнопку Mini App, пользователь подтверждает конкретную запись. После успешной загрузки Telegram сообщение получает правильные title и performer из MusicBrainz, а SQLite атомарно связывает его MBID с загруженным аудио. Обычный поиск /yt не назначает MBID автоматически. Разные записи с похожими заголовками не сливаются без подтверждения.
- Никакие cookie-файлы, авторизация YouTube, PO Token или обход DRM не передаются автоматически.
- YouTube меняет защиту, форматы и правила. Попытка извлечения может завершиться ошибкой, в том числе из-за ограничения клиента или обязательного PO Token. Ничего не обещаем до испытаний на настоящем сервере.
- Использовать для материалов, на скачивание которых есть право, с соблюдением условий источника.

## Что ещё отсутствует

- Полная автоматическая проверка соответствия оригиналу/ремиксу с аудиофингерпринтами. Сейчас есть только эвристический поиск-подсказка, а не достоверная идентификация.
- Музыкальные обложки, нормализация ID3, импорт альбомов и плейлистов, полноценное качество звука.
- End-to-end **реальные** тесты Telegram и YouTube. В CI уже проверен полностью связанный путь с подставным YouTube-источником и Bot API, но это не настоящий сетевой запуск.
- Гарантированный внешний кеш и автоматическое воспроизведение видео.
