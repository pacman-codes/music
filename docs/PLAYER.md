# Нативное прослушивание и честные ограничения

## Сейчас

- Telegram Bot API sendAudio / sendMediaGroup передаёт готовые файлы, сохранённые Telegram ранее.
- На каждые 1–10 треков создаётся одна порция. Длинную очередь продолжают кнопкой «Ещё 10».
- После каждой порции бот присылает **одну** компактную панель с кнопками ⭐ под все треки этой порции. Нажатие открывает оценки 1–10 и ручные отметки пропуска/дослушивания. Эта панель — стандартная inline-клавиатура, не экспериментальный HTML-виджет.
- Очередь (snapshot треков), позиция и отправка сохраняются в SQLite.
- Прежде чем увеличить позицию, бот получает успешный ответ от Telegram. Сетевая ошибка не двигает позицию; возможна повторная отправка при редком таймауте после фактического приёма Telegram.
- История в базе — **отправленные** треки, не доказанные прослушивания.
- Фоновое воспроизведение, переключение и локальный кеш — возможности мобильного клиента Telegram. Их работоспособность и точную последовательность аудио на iOS/Android требуется проверить на устройствах.

## Чего Telegram не даёт

- Нет встроенной возможности обернуть любую внешнюю медиа-ссылку в нативное audio/video сообщение без передачи файла Telegram.
- Нет реальных событий play / pause / skip / completed, доступных боту.
- Нельзя программно перехватить кнопки блокировки экрана через Bot API.
- Telegram Mini App не является гарантированным фоновым аудиоплеером.

## Будущие рекомендации

ListenBrainz, Last.fm и MusicBrainz могут поставлять кандидатов и идентификаторы, но поиск кандидата не означает наличия файла в Telegram. Потребуется независимый, проверяемый ingest с учетом прав на контент. Для доступности офлайн — оригинальные файлы, на которые есть право загрузки, в архивном канале; metadata и file_id в SQLite.

## Проверка на реальном телефоне

1. Запустить /wave с 20+ треками, послушать первую порцию.
2. Экран блокировки: фоновое аудио, переключение, пауза, работа при очистке локального кеша.
3. Нажать «Ещё 10» и проверить порядок, отсутствие дублей.
4. Проверить поведение при временно недоступном file_id и нестабильном соединении.
5. Проверить ограничения на большие видео отдельно, без обещаний безлимитного потока.
