# Опциональное распознавание AcoustID и локальные теги

## Конфигурация

```env
MUSIC_WITH_FINGERPRINT=true
ACOUSTID_CLIENT_KEY=
```

Ключ приложения получают по правилам сервиса AcoustID. Заполнять его **только** в приватном `.env` будущего сервера, никогда не в GitHub, URL или пользовательские сообщения. `MUSIC_WITH_FINGERPRINT=true` при сборке Docker устанавливает `libchromaprint-tools` (команда `fpcalc`). Если ключ пуст, API/кнопка распознавания выключены.

## Работа

`/fingerprint 12` или «🧬 Узнать песню» в Mini App:

1. Сервер получает существующий Telegram `file_id` и скачивает **до 19 МиБ** временно через Bot API, если обычное скачивание доступно.
2. `fpcalc` вычисляет Chromaprint-отпечаток. AcoustID возвращает возможные MusicBrainz recording MBID и оценки уверенности.
3. SQLite хранит лишь SHA256 отпечатка и его длительность для сопоставления возможных повторов. Повтор может отличаться при иных кодировках; совпадение не доказывает полную идентичность.
4. Владелец сам выбирает правильную запись через кнопку «🔗 Подтвердить», как и в обычном MusicBrainz-поиске.
5. `/tag 12` или «🏷 Обновить теги» переносит **подтверждённые** title/artist в SQLite для использования при последующих `sendAudio`. **Это не исправляет ID3 внутри уже загруженного Telegram-файла**, поскольку `file_id` не изменяет хранимые байты.

Ограничения: временный файл удаляется после обработки; не принимаются произвольные внешние URL; сетевые запросы ограничены временем, размером и общим SQLite rate limiter. AcoustID — поисковая подсказка; разные издания и live/cover нельзя связывать автоматически. Большие Telegram-файлы и файлы без доступного download_file невозможно обработать этим методом. Реальный end-to-end AcoustID и мобильный UX пока не проверены.

Официальные ссылки: https://acoustid.org/webservice и https://acoustid.org/chromaprint
