# Прямой MP3/M4A → Telegram

**Статус:** код и офлайн-тесты в репозитории; реальная отправка в Telegram не тестировалась, потому что сервер ещё не развёрнут.

## Что сделано

В отдельном Mini App «Новая музыка» можно найти MusicBrainz-запись. Если на сервере настроен список доверенных хостов, появится кнопка **📥 В Telegram**.

Импорт также работает **без Mini App**: в чате с ботом сначала `/find название`, затем для известного MBID команда `/import MBID https://доверенный-хост/track.mp3`. При новом импорте бот присылает нативное аудиосообщение. Если файл уже существует в Telegram, бот повторно отправит его по `file_id` без скачивания. Пользователь вручную вводит **прямую** ссылку на MP3 или M4A, который ему разрешено скачать.

Backend на сервере проверяет, что эта запись была получена из MusicBrainz/ListenBrainz, URL идёт по HTTPS на хост из allowlist, формат .mp3/.m4a, ответ выглядит как аудио и не превышает 45 МБ. Он скачивает файл во временную папку, отправляет как `sendAudio` от бота в личный чат, получает Telegram `file_id`, сохраняет связь с записью каталога в SQLite и **удаляет временный файл**. При повторном запросе уже сохранённого трека скачивание не повторяется.

**Это не YouTube/Torrent resolver**: MusicBrainz возвращает только метаданные. Ссылку нужно предоставить отдельно, из источника с разрешённой загрузкой.

## Настройка после подготовки сервера

В отдельном приватном `.env`, не в Git:

```env
MUSIC_ALLOWED_MEDIA_HOSTS=audio.example.org,media.example.net
```

Указывать только реальные доверенные домены, на которых есть разрешённые MP3/M4A, без `http://`, путей, звёздочек и портов. По умолчанию переменная пуста и функция недоступна. Разрешённый хост сравнивается строго (не суффикс и не любой субдомен), HTTP-редиректы не выполняются, IP и локальные домены запрещены.

Пример ссылки: `https://audio.example.org/album/song.mp3`. Это пример, не действительный источник.

## Ограничения

- Обычный облачный Telegram Bot API: отправка `multipart/form-data` до 50 МБ; наш лимит 45 МБ даёт запас. MP3/M4A для музыкального плеера. Telegram media file_id повторно используется без загрузки. Документация: https://core.telegram.org/bots/api#sending-files
- Во время импорта файл до 45 МБ **временно** занимает диск (`/tmp`). Никакого постоянного аудиоархива на VPS нет.
- Суммарное время загрузки не более 90 секунд. На пользовательские источники не отправляется токен Telegram.
- Общая SQLite lease-блокировка для одного MusicBrainz MBID предотвращает повторное параллельное скачивание между bot и web; после ошибки она освобождается, а при падении процесса истекает через 15 минут. Для общей квоты по всем одновременно загружаемым песням ещё нужен единый worker/очередь.
- URL с разрешённым именем хоста может изменить DNS-адрес; оператор должен добавлять в allowlist только доверенные домены, а не домены случайных файловых хостингов.
- Признаки MP3/M4A проверяются по MIME, расширению и нескольким начальным байтам — это не антивирусная проверка и не полная валидация кодека.
- Если Telegram успел принять файл, но соединение оборвалось до подтверждения, может понадобиться проверка сообщений, чтобы избежать дублей.
- Нет перекодирования, DRM-обхода, автоматического yt-dlp и импорта фильмов. Работа со сторонним контентом только при разрешённом скачивании.

## YouTube как отдельный отключаемый источник

Команды `/yt` и `/ytget` используют `yt-dlp` и FFmpeg, а не allowlisted прямой HTTP-файл. Для них нужен расширенный Docker-образ и отдельные флаги, см. [docs/YOUTUBE.md](YOUTUBE.md). Получение файлов с YouTube не гарантировано и допускается только в рамках прав и условий источника.
